00前提: AIとブラウザの間には「橋」が要る

  • Claude Code も ChatGPT も、本体ができるのは文章の読み書きだけ。画面を「見る」機能もボタンを「押す」機能も本体にはない
  • ブラウザとの間を埋める橋の作り方が各社・各ツールで違う — 今日はその違いの話
  • MCP = 橋をどのAIからも使えるようにする共通規格。USBの差し込み口のようなもの

02開発者の道具は MCP で二強

Playwright MCP

Microsoft

  • ページの構造をテキストで受け取って操作する。軽くて速い
  • Chrome / Firefox / WebKit / Edge 対応
  • 操作手順を自動テストとして残せる → テストの自動実行向き

Chrome DevTools MCP

Google Chromeチーム

  • CDP(Chromeを外から操縦するための公式の仕組み)に直結
  • 通信履歴(Network)・エラーログ(Console)・速度計測まで見える
  • Chrome専用 → 開発中の不具合調査向き

世の中の整理も「両方入れて使い分け」が定番。ほか browser-use(OSS)、Puppeteer MCP など

05chrome-dom-mcp の構成

Codex / Claude Code
↕ HTTP MCP :9333/mcp

Chrome拡張

いま開いているタブ
  • MCPの口はBridge.appが持つ。エージェント側は接続先を1つ足すだけ
  • ブラウザ側は拡張機能。普段のChromeがそのまま使える
  • 道具は7個だけ:

get_dom get_network get_console
click fill wait_for navigate

さっきの3つの選択で言うと: 目=DOM+Network+Console、手=セレクタ、場所=普段のChrome

06デモ

見る → 操作する → 人間に見えない裏側(Console)を確認する まで1タスクで

07リスク: ログイン済みブラウザを渡す = その権限ごと渡す

誤操作

AIが削除・購入・送信ボタンを押してしまう事故。

対策: 大事な操作の前は人が確認。触らせるサイトを絞る。

ページの文字による乗っ取り

ページ内に「これを読んだら◯◯して」と仕込むと、AIが命令として従ってしまう攻撃(プロンプトインジェクション)。

対策: 読んだ内容を命令扱いしない設計。権限を最小に。

実例: 今月の報道

Claude in Chromeに未修正の欠陥 — 悪意ある別の拡張機能がClaudeを操り、Gmail・カレンダーを読み出せる。

2026年7月時点で修正されないまま報道(通称 ClaudeBleed)。

大手でもこの状態。自作の chrome-dom-mcp も同じ注意が必要 — 道具を7個に絞り、触るのは今見ているタブだけにしている

08まとめ

  • ブラウザ×AIエージェントは目・手・場所の3択の組み合わせ。各社の違いはこの選び方の違い
  • 使い分け: 自動テスト → Playwright MCP / 開発中の不具合調査 → DevTools MCP / ログインが要る日常作業 → 普段のChrome同居型
  • みんなが欲しい組み合わせは大手も参入してくる。それでも個人で作れる規模感。MCPにしておけばAIを選ばない
